# Actions Loader — загрузчик готовых сборок из GitHub Actions

Android-приложение: находишь репозиторий → видишь запуски **GitHub Actions** → скачиваешь **готовые артефакты сборки** (APK, ZIP, бинарники) прямо в «Загрузки» и ставишь APK в один тап.

**Файл для установки:** `ZI-Git-v2.1.apk` (Android 8.0+, 90 КБ)
Копия в проекте: `ghactions-app/out/ZIGit.apk`

> В исходниках версия **3.1** (versionCode **15**): удаление репозиториев и артефактов.
> Одна и та же сборка получается локально (`./build.sh`) и в GitHub Actions
> (артефакт `ZI-Git-APK`). Файл `ZI-Git-v2.1.apk` в корне — старая сборка.

**Разработчик:** Захаревич Игорь · ziv@csl.by (указан в шапке приложения — тап открывает письмо, и в разделе «О программе»)

Подпись: **постоянный release-ключ ZI Git** (RSA 4096, SHA384withRSA, действует до 2056 года).
Ключ лежит в `keystore/zigit-release.jks`, пароль и отпечатки — в `keystore/README.txt`.
Обновления, подписанные этим ключом, ставятся поверх без удаления приложения.

### Версионирование (3.1)

Нумерация приведена к единой шкале репозитория: 2.1 → **3.1**.

| | versionCode | versionName |
|---|---|---|
| сборка 2.1 (файл в корне) | 5 | 2.1 |
| сборка 3.0 (другие ветки) | 14 | 3.0 |
| **эта сборка** | **15** | **3.1** |

versionCode 15 больше 14, поэтому APK ставится **поверх 3.0 без удаления** приложения.
Если versionCode новой сборки меньше установленного, Android отказывает с сообщением
«Приложение не установлено, так как его пакет недействителен» — именно это произошло
при попытке поставить сборку 2.2 (versionCode 6) поверх 3.0 (versionCode 14).
Проверить версии можно так: в приложении ⋮ → «О приложении и разработчике», либо
`aapt2 dump badging ZIGit.apk | head -1`.

## Приватные репозитории не видны (разобрано на живом примере)

Симптом: в дашборде GitHub у вас 8 репозиториев, а приложение показывает 1.

Это **не баг приложения**: GitHub в ответе `/user/repos` перечисляет только те репозитории, на которые выдан доступ **самому токену**. Приватные репозитории, не включённые в токен, просто отсутствуют в ответе (без ошибки). Публичные видны любому токену — поэтому `PC-Tools` показывался.

Как это проверяется (на примере аккаунта `zigorminsk-debug`):

| Проверка | Результат |
|---|---|
| Дашборд GitHub (скриншот пользователя) | 8 репозиториев |
| Публичная страница `github.com/<аккаунт>?tab=repositories` | **1** репозиторий → остальные 7 приватные |
| `/user` по токену | `public_repos: 1` |
| `/user/repos?visibility=private` по токену | **0** → токену доступ к приватным не выдан |
| `/user/orgs` | 0 организаций |

**Как починить (любой из вариантов):**

* **Classic токен (проще всего).** Приложение: ⋮ → Токен GitHub → «Создать classic токен (repo + workflow)» → галочки уже проставлены → Generate → скопировать → вставить в приложение. Такой токен сразу видит все ваши приватные репозитории и организации.
* **Fine-grained токен.** GitHub → Settings → Developer settings → Fine-grained tokens → ваш токен:
  1. **Resource owner** = ваш личный аккаунт (или организация);
  2. **Repository access** → «All repositories» (либо «Only select repositories» и выбрать все нужные);
  3. **Permissions → Repository permissions**: `Metadata: Read-only` (**обязательно**), `Actions: Read-only` (для запусков и артефактов), `Contents: Read-only` (для ZIP исходников и релизов);
  4. Save. Значение токена при этом не меняется — в приложении достаточно нажать «Обновить».

## Другие причины, почему список короткий

GitHub отдаёт по токену **только те репозитории, на которые у токена есть доступ**. Проверить, сколько видит конкретный токен, можно прямо в приложении: ⋮ → **Токен GitHub** → **Проверить, что видит токен**.

Типовые причины:

| Причина | Как выглядит | Что делать |
|---|---|---|
| У аккаунта действительно один проект | `Публичных репозиториев на аккаунте: 1` | Токен создан для другого (например, тестового) аккаунта — создайте токен в том аккаунте, где лежат проекты |
| Fine-grained токен выдан только на часть репозиториев | `Тип токена: fine-grained`, видно мало репозиториев | GitHub → Settings → Developer settings → **Fine-grained tokens** → ваш токен → **Repository access** → «All repositories»; права: **Actions: Read-only**, **Contents: Read-only**, **Metadata: Read-only** |
| Classic токен без scope `repo` | `Скоупы: (нет!)` или список без `repo` | Пересоздайте токен с галочками `repo` и `workflow` |
| Проекты в организации | `Организаций: 0` | Для fine-grained токена выберите **Resource owner = организация** (и чтобы орг разрешала fine-grained токены); classic токен видит организационные репозитории сразу при scope `repo` |
| Проекты в другом аккаунте GitHub | `Аккаунт токена: <login>` не тот, что нужен | Войдите в нужный аккаунт и создайте токен там; либо откройте публичный проект через поиск 🔍 — он не зависит от токена |

**Важно про безопасность:** не пересылайте токен в чатах и тикетах. Если он куда-то попал — сразу отзовите: GitHub → Settings → Developer settings → Personal access tokens → ваш токен → **Revoke**, и выпустите новый.

## Возможности

| Экран | Что делает |
|---|---|
| **Главный** | Ввод `owner/repo` (можно вставить ссылку `https://github.com/owner/repo` — распознаётся автоматически), список запусков Actions с бейджем статуса (`success` / `failure` / `in_progress`), ветка, номер запуска, коммит, время. Удержание запуска — открыть / удалить его артефакты / открыть на GitHub |
| **Артефакты** | Все артефакты запуска: имя, размер, дата, число скачиваний, статус «истёк». Кнопка **Скачать** с прогрессом в процентах и МБ. Удержание строки или меню ⋮ — **удаление артефактов** с GitHub |
| **Релизы** | Готовые файлы из релизов (фильтр «только APK»). Публичные релизы качаются **без токена** |
| **Мои репозитории** | Список своих репозиториев по токену + поиск по всем репозиториям GitHub. Удержание строки — **удаление репозитория** (с вводом имени для подтверждения) |
| **ZIP исходников** | Скачивание исходников репозитория (zipball) в «Загрузки» |
| **Скачанные файлы** | Всё, что загружено из GitHub: открыть, установить APK, поделиться, удалить |
| **Токен GitHub** | Ввод/очистка токена, проверка «что видит токен», кнопки создания токена |

Навигация: нижняя панель **Запуски · Релизы · Мои репо · Файлы**; на внутренних экранах — кнопка «‹» назад.

Мелочи, которые важны на практике:

* Скачанный артефакт сохраняется как `Имя-артефакта.zip` в общую папку **«Загрузки»** (Android 10+ — через MediaStore, без разрешений).
* Если внутри архива есть **APK** — приложение предлагает его установить (само запросит разрешение «Установка неизвестных приложений»).
* Артефакты подтягиваются ко всем запускам параллельно, есть фильтр «только запуски с артефактами».
* Прогресс-бар с реальными процентами и объёмом, понятные тексты ошибок (401/403/404/410 — в том числе «артефакт истёк»).
* Никаких внешних библиотек и телеметрии: только `HttpURLConnection` + `org.json` из самой Android. Токен хранится локально в `SharedPreferences` приложения и никуда не отправляется, кроме `api.github.com`.

## Установка

1. Скачай `ActionsLoader-v1.0.apk` на телефон.
2. Открой файл → разреши установку из этого источника (Android спросит один раз).
3. Если Play Protect ругается на «неизвестного разработчика» — это нормально для APK, подписанного debug-ключом. Можно нажать «Установить всё равно» (или собрать APK своим ключом, см. ниже).

Требования: **Android 8.0 (API 26) и выше**, интернет.

## Как пользоваться

1. **Введи репозиторий.** Например: `termux/termux-app` или `AnabasaSoft/MantPro` (у второго в Actions лежит настоящий APK на 144 МБ).
2. **Открой запуск.** В строке запуска видно, сколько у него артефактов: `Артефактов: 2 (38.4 МБ) →`.
3. **Нажми «Скачать»** у нужного артефакта. Файл появится в «Загрузках», а если внутри APK — предложит установку.

### Про токен (важно)

GitHub отдаёт **метаданные** артефактов публично, но **сами файлы — только авторизованным запросам** (даже у публичных репозиториев). Поэтому для скачивания артефактов нужен токен:

1. GitHub → *Settings → Developer settings → Personal access tokens → Tokens (classic)* → **Generate new token**.
2. Поставь галочку **`repo`** (для приватных репозиториев; для публичных достаточно `public_repo`), при желании **`workflow`** для чтения Actions и **`delete_repo`**, если нужно удалять репозитории из приложения.
3. Скопируй токен (`ghp_…`) и вставь его в приложении: **⋮ → Токен GitHub**.

Приложение подсказывает это само: жёлтый баннер на главном экране и диалог «Нужен токен GitHub» при первой попытке скачать артефакт.

Без токена всё равно работает: список запусков, список артефактов, **релизы** и **ZIP исходников** публичных репозиториев.

## Удаление репозиториев и артефактов

Удалить можно и репозиторий целиком, и отдельные артефакты сборки — не выходя из приложения.

| Что удаляем | Где в приложении | Подтверждение |
|---|---|---|
| Репозиторий | «Мои репо» → удержать строку → «Удалить репозиторий…»; главный экран → ⋮ → «Удалить репозиторий…» | нужно ввести полное имя `owner/repo`, как на сайте GitHub |
| Один артефакт | экран артефактов → удержать строку → «Удалить артефакт» | обычный диалог: имя и размер |
| Все артефакты запуска | экран артефактов → ⋮ → «Удалить все артефакты»; либо удержать запуск на главном экране → «Удалить артефакты запуска (N)» | обычный диалог: количество и суммарный размер |

**Что нужно токену для удаления:**

| Действие | classic-токен | fine-grained токен |
|---|---|---|
| Удалить репозиторий | scope `delete_repo` (+ `repo` для приватных) | Repository permissions → **Administration: Read and write**, **Metadata: Read-only** |
| Удалить артефакт | scope `repo` (нужен и для публичных репозиториев) | Repository permissions → **Actions: Read and write**, **Metadata: Read-only** |

Удалять можно только то, на что у владельца токена есть права администратора: чужой публичный репозиторий
из поиска удалить нельзя (GitHub ответит `403` — приложение объяснит причину и предложит исправить токен).

Реализация — те же два вызова GitHub REST API, что и на сайте:
`DELETE /repos/{owner}/{repo}` и `DELETE /repos/{owner}/{repo}/actions/artifacts/{artifact_id}`.
Запросы выполняются в фоновом потоке, прогресс удаления пачки артефактов показывается в диалоге
(«Удаляю артефакты: 3 из 8…»), а частичный отказ не отменяет уже выполненные удаления.

## Ограничения, о которых стоит знать

* **Артефакты живут ограниченное время.** По умолчанию GitHub хранит артефакты 90 дней (настраивается в workflow), затем удаляет — в приложении такие помечаются как «Истёк».
* **Артефакт — это всегда ZIP.** Даже если workflow загрузил один APK, GitHub отдаёт его внутри архива. Приложение распаковывает архив и достаёт APK само.
* **Артефакты не появляются сами по себе**: нужен шаг `actions/upload-artifact` в workflow. Если у запуска их нет, приложение так и напишет.
* Скачивание идёт в один поток — большие артефакты (100+ МБ) качаются небыстро, но с честным прогрессом.
* Лимиты GitHub: 60 запросов/час без токена, 5000/час с токеном.
* **Удаление необратимо**: GitHub не восстанавливает ни удалённый репозиторий (вместе с ветками,
  Actions, релизами), ни удалённые артефакты. Поэтому репозиторий удаляется только после ввода имени.
* Подпись — **debug-ключ** (для личной установки). Для публикации в Google Play нужен свой release-ключ и сборка `release` (см. ниже).

## Сборка в GitHub Actions (артефакт с APK)

Готовые сборки в Actions появляются только там, где в workflow есть шаг
`actions/upload-artifact`. В этом репозитории такого workflow раньше не было (папки
`.github/workflows` не существовало), поэтому у запусков не было ни одного артефакта.
Теперь он есть: **`.github/workflows/build-apk.yml`**.

Что делает workflow «Build APK»:

1. ставит JDK 21 и Android SDK (build-tools 34, platform 34);
2. собирает APK тем же `build.sh`, что и локально (без Gradle), и подписывает постоянным ключом;
3. публикует результат артефактом **`ZI-Git-APK`** (внутри `ZIGit.apk`, хранится 30 дней);
4. для тегов `v*` дополнительно прикладывает APK к релизу.

Как получить сборку:

* **Автоматически** — при push в `main` и при открытии pull request;
* **Вручную** — GitHub → Actions → **Build APK** → **Run workflow** → выбрать ветку → Run.
  Для веток, которых нет в `main`, ручной запуск доступен после того, как файл workflow
  попал в `main` (или через pull request — он тоже запускает сборку);
* затем в приложении ZI Git: запуск «Build APK» → «Скачать» → `ZI-Git-APK.zip` → внутри APK.

Секреты не нужны: ключ подписи `keystore/zigit-release.jks` лежит в репозитории,
пароль по умолчанию — в `build.sh` (его можно задать через `ZIGIT_KEYSTORE_PASS`).
Если публиковать APK в Google Play или хранить ключ отдельно — перенесите keystore в secrets
и передайте путь/пароль переменными окружения.

Шаблон для своих Android-проектов (Gradle, `assembleDebug` + `upload-artifact`) —
в `example-workflow/android-build.yml`.

## Пересборка из исходников

```bash
./setup-android-sdk.sh   # окружение: JDK 21 + Android SDK 34 + R8 (один раз на сессию)
./build.sh               # сборка и подпись -> ghactions-app/out/ZIGit.apk
```

Скрипт делает всё без Gradle: `aapt2 compile` → `aapt2 link` → `javac` → `D8` (R8 из Google Maven, потому что встроенный в build-tools d8 падает с NPE на JDK 21) → упаковка → `zipalign` → `apksigner` **постоянным ключом** `keystore/zigit-release.jks`.

Сменить пароль/путь к ключу можно переменными окружения:

```bash
ZIGIT_KEYSTORE=/путь/мой.jks ZIGIT_KEYSTORE_PASS='пароль' ./build.sh
```

## Структура проекта

```
.github/workflows/build-apk.yml  # CI: сборка APK + артефакт ZI-Git-APK
example-workflow/                # шаблон workflow для чужих Gradle-проектов
keystore/
├── zigit-release.jks            # ПОСТОЯННЫЙ ключ подписи (храните копию!)
└── README.txt                   # пароль, отпечатки, инструкции
setup-android-sdk.sh             # установка окружения для сборки
build.sh                         # сборка + подпись
ghactions-app/
├── AndroidManifest.xml          # 4 экрана, FileProvider для установки APK
├── res/                         # layouts, drawables, values, иконки (PNG + adaptive)
├── src/com/zigit/app/
│   ├── MainActivity.java        # поиск репозитория, запуски Actions, артефакты к ним
│   ├── ArtifactsActivity.java   # артефакты запуска + скачивание + установка APK
│   ├── ReleasesActivity.java    # файлы релизов (работает без токена)
│   ├── RepoPickerActivity.java  # мои репозитории / поиск
│   ├── Api.java                 # GitHub REST API, GET/DELETE, редиректы, прогресс
│   ├── GithubDelete.java        # удаление репозиториев и артефактов + разбор прав токена
│   ├── FileProviderX.java       # content:// URI для установщика APK
│   ├── Models.java, Store.java, Util.java, TokenDialog.java
│   └── ...
└── lib/r8.jar                   # инструмент dex-компиляции (без Gradle)
```
