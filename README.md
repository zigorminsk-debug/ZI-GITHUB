# ZI Git 3.3 — загрузчик сборок из GitHub Actions

Android-приложение для загрузки готовых сборок (APK, ZIP, бинарников) из GitHub Actions. Находите репозиторий → видите запуски → скачиваете артефакты и устанавливаете APK в один тап.

**Что нового в 3.3** (versionCode **32**):
- **Очистка конкретного репозитория с сохранением последних успешных сборок**: «Оставить 2 последних успешных» (есть и 1, и 3) — удаляются артефакты всех остальных запусков, а идущие сейчас сборки не трогаются.
- Тот же режим для всего аккаунта: «Оставить по 2 последних успешных в каждом репозитории».
- Открывается из «Мои репо» (удержание репозитория), из меню экрана «Артефакты» и из ⋮ на главном экране.

**Что нового в 3.2** (versionCode **31**):
- **Очистка хранилища** — экран, который сканирует все репозитории и массово удаляет артефакты и кэши Actions. Нужен, когда GitHub отвечает **«Artifact storage quota has been hit»**: у бесплатного плана общее хранилище Actions — 500 МБ на аккаунт.
- Готовые фильтры: артефакты старше 7 / 30 дней, истёкшие, все артефакты, все кэши. Показываются количество и объём, удаление идёт пачкой с прогрессом.
- Быстрый доступ: ⋮ на главном экране, ⋮ на экране артефактов, ⋮ в «Мои репо» и кнопка 🧹 в шапке «Мои репо»; на экране «Хранилище» — кнопка «Очистить».
- Плюс «Очистить артефакты этого репозитория» в меню удержания репозитория.

**Что нового в 3.1** (versionCode **30**):
- **Удаление репозиториев и артефактов** с GitHub прямо из приложения (с подтверждением и разбором прав токена).
- **Экран «Хранилище GitHub»** — сколько места занято и сколько осталось: аккаунт, репозитории, артефакты и кэш Actions, данные биллинга.
- **Проверка скачанного APK** (zip, манифест, dex, подпись), копия APK в «Загрузки», показ размера и SHA-256.
- Сборка подписывается явно схемами **v1 + v2 + v3**, `apksigner verify` в CI обязателен.
- Всё из 3.0 сохранено: создание репозитория, загрузка файлов, редактирование репозитория, логи сборки, инструкция, автообновление.

## 📥 Установка

1. Скачайте **ZI-Git.apk** из [Releases](https://github.com/zigorminsk-debug/ZI-GITHUB/releases/latest)
2. Откройте файл на телефоне
3. Разрешите установку из этого источника (Android спросит один раз)
4. Play Protect может предупредить — это нормально для APK вне Google Play, нажмите «Установить всё равно»

**Требования:** Android 8.0 (API 26) и выше, интернет.

## 🔑 Подключение к GitHub (токен)

Для скачивания артефактов нужен токен GitHub. Без токена работают: список запусков, список артефактов, релизы и ZIP-исходники публичных репозиториев.

### Как получить токен

**Вариант 1: Classic-токен (проще всего)**

1. В приложении: **⋮ → Токен GitHub**
2. Нажмите **«Создать classic токен (repo + workflow)»** — откроется страница GitHub
3. Галочки `repo` и `workflow` уже проставлены
4. Нажмите **Generate token**
5. Скопируйте токен (`ghp_…`) и вставьте в приложение

**Вариант 2: Fine-grained токен**

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate
2. **Resource owner** = ваш аккаунт (или организация)
3. **Repository access** → «All repositories»
4. **Permissions → Repository permissions:**
   - `Metadata: Read-only` (обязательно)
   - `Actions: Read-only` (запуски и артефакты)
   - `Contents: Read-only` (ZIP и релизы)
   - `Administration: Read and write` (создание и редактирование репозиториев)
5. Save → скопируйте токен → вставьте в приложение

### Ввод токена в приложении

- **⋮ → Токен GitHub** — ввод/очистка токена
- Жёлтый баннер на главном экране — нажмите, чтобы ввести токен
- При первой попытке скачать артефакт без токена — появится диалог с предложением ввести

### Приватные репозитории

Приватные репозитории видны **только** токену с доступом к ним. Если список репозиториев короче ожидаемого:
- **⋮ → Токен GitHub → Проверить, что видит токен** — диагностика
- Для fine-grained токена: **Repository access → All repositories**

## 📱 Экраны и навигация

### Главный экран — «Запуски»

Основной экран приложения. Сверху — строка ввода репозитория и кнопки, ниже — список запусков GitHub Actions.

| **↻** | Обновить список запусков |
| **⋮** | Меню (см. ниже) |

#### Поле ввода и кнопки

| Элемент | Что делает |
|---------|-----------|
| **owner/repo** | Введите репозиторий (например `termux/termux-app` или `zigorminsk-debug/PC-Tools`). Поддерживаются ссылки `https://github.com/owner/repo` |
| **Найти** | Загрузить запуски Actions указанного репозитория |
| **Мои репо** | Список ваших репозиториев по токену + поиск по GitHub |

#### Жёлтый баннер

Появляется, если токен не введён. Нажмите → откроется диалог ввода токена.

#### Список запусков

Каждый запуск показывает:
- **Название** (заголовок запуска)
- **Бейдж статуса:** `success` (зелёный), `failure` (красный), `⏳ in_progress` (жёлтый), `queued`
- **Номер, workflow, ветка, коммит, время**
- **Артефакты:** количество и размер (после загрузки)
- **▶ Сборка идёт** — для незавершённых запусков

**Действия с запуском:**
- **Тап** → экран артефактов (для завершённых) или экран прогресса (для in_progress)
- **Удержание** → контекстное меню:
  - **Артефакты** — открыть артефакты
  - **Логи сборки** — просмотр логов и ошибок
  - **Копировать: #N** — скопировать номер и описание
  - **Открыть на GitHub** — открыть запуск в браузере
  - **🗑 Удалить артефакты запуска (N)** — удалить сборки этого запуска с GitHub

### Экран «Логи сборки»

Открывается кнопкой ☰ в артефактах или через long-press на запуск.

**Список заданий (jobs):**
- Каждая job: имя, статус, время, runner, количество шагов
- Ошибочные шаги подсвечены

**При тапе на job — полный лог** с цветовой подсветкой:
- 🔴 **Красный + жирный** — ошибки (`error:`, `failed`, `fatal:`)
- 🟡 **Жёлтый** — предупреждения (`warning:`, `deprecated`)
- 🟢 **Зелёный** — успешные шаги (`✓`, `build successful`)
- 🔵 **Голубой** — заголовки секций (`Run …`)

| Элемент | Что делает |
|---------|-----------|
| **‹** | Назад к списку jobs / назад к запуску |
| **Копировать** | Скопировать весь лог в буфер обмена |
| **↗** | Поделиться логом через любое приложение |
| **↻** | Обновить список jobs |

**Выделение текста:** long-press на текст лога → стандартное выделение Android → «Копировать».

**Прогресс сборки (для in_progress):**
- Автообновление каждые 5 секунд
- Прогресс-бар: выполнено шагов / всего
- Шаги с иконками: ✓ успех, ✗ ошибка, ▶ выполняется, ○ в очереди

## 🔄 Обновления приложения

**Автоматическая проверка:**
- При запуске приложения (тихо, в фоне, не чаще раза в 4 часа)
- Если есть новая версия — диалог с предложением обновить

**Ручная проверка:**
- **⋮ → О приложении → «Проверить обновления»**

**Процесс обновления:**
1. Диалог: версия, размер, описание изменений
2. «Скачать и установить» — скачивание с прогрессом
3. Автоматический запуск установщика
4. Установка поверх текущей версии (тот же ключ подписи)

## 🗑 Удаление репозиториев и артефактов

| Что удаляем | Где | Подтверждение |
|---|---|---|
| Репозиторий | «Мои репо» → удержать строку → «🗑 Удалить репозиторий…»; главный экран → ⋮ → «🗑 Удалить репозиторий…» | нужно ввести полное `owner/repo`, как на сайте GitHub |
| Один артефакт | экран «Артефакты» → удержать строку → «🗑 Удалить артефакт» | имя и размер |
| Все артефакты запуска | экран «Артефакты» → ⋮ → «🗑 Удалить все артефакты»; или удержать запуск на главном → «🗑 Удалить артефакты запуска (N)» | количество и суммарный размер |

Права токена:

| Действие | classic | fine-grained |
|---|---|---|
| Удалить репозиторий | scope `delete_repo` (+ `repo` для приватных) | **Administration: Read and write** + Metadata: Read-only |
| Удалить артефакт | scope `repo` (нужен и для публичных) | **Actions: Read and write** + Metadata: Read-only |

Удалить можно только то, где у владельца токена есть права администратора. При `403/404`
приложение объясняет, чего не хватает, и предлагает открыть настройки токена.

Эндпоинты: `DELETE /repos/{owner}/{repo}` и
`DELETE /repos/{owner}/{repo}/actions/artifacts/{artifact_id}`. Пачка артефактов удаляется
последовательно с прогрессом, частичный отказ не отменяет уже выполненные удаления.

## 🧹 «Artifact storage quota has been hit» — что делать

Такую ошибку возвращает GitHub, когда закончилось **общее хранилище Actions** аккаунта:
у бесплатного плана это 500 МБ, и в него входят артефакты и кэши **всех** репозиториев
(для публичных репозиториев — бесплатно, приватные считаются в квоту). Пока квота занята,
`actions/upload-artifact` в workflow падает, и новые сборки не появляются.

Приложение теперь умеет освобождать место: **⋮ → «🧹 Очистка хранилища»**
(или кнопка 🧹 в шапке «Мои репо», или кнопка «Очистить» на экране «Хранилище»).

Экран сканирует доступные токену репозитории (до 60) и показывает:

| Что видно | Откуда |
|---|---|
| Артефакты сборок: количество и суммарный объём | `GET /repos/{repo}/actions/artifacts` (все страницы) |
| Кэши Actions: количество и суммарный объём | `GET /repos/{repo}/actions/caches` |
| «Всего можно освободить» | сумма того и другого |

### Очистка одного репозитория с сохранением последних сборок

Если нужен не тотальный сброс, а аккуратная чистка: «Мои репо» → удержать репозиторий →
**«🧹 Очистить: оставить 2 последних успешных»** (то же — ⋮ на главном экране и ⋮ на экране
«Артефакты» для открытого репозитория).

Что происходит:

1. читаются запуски репозитория (`/actions/runs`), берутся **2 последних с `conclusion=success`**;
2. их артефакты **остаются**; артефакты сборок, которые идут прямо сейчас (`in_progress`, `queued`), тоже не трогаются;
3. удаляются артефакты всех остальных запусков (артефакты без привязки к запуску не трогаем);
4. перед удалением показывается, какие именно запуски останутся (`#128 · main, #125 · main`), сколько артефактов удалится и сколько места это освободит.

Можно оставить 1 или 3 последних успешных — кнопки рядом. Есть и кнопки «всё удалить»
(все артефакты или все кэши этого репозитория) и «старше 30 дней».

В режиме всего аккаунта появилась кнопка **«Оставить по 2 последних успешных в каждом
репозитории»** — проходит по всем доступным репозиториям и чистит по тому же правилу.

Действия для всего аккаунта (перед удалением показывается количество, объём и число репозиториев):

* **Артефакты старше 7 дней**;
* **Артефакты старше 30 дней**;
* **Истёкшие артефакты** — их GitHub всё равно удалит;
* **Все артефакты сборок**;
* **Все кэши Actions** — кэш пересоздастся сам при следующей сборке.

Удаление идёт последовательно с прогрессом («Удаляю артефакты: 12 из 48 · owner/repo»),
в конце — отчёт: сколько удалено и сколько места освобождено. Отказы по правам
(403/404) показываются отдельно: нужны `Actions: Read and write` (fine-grained)
или scope `repo` (classic).

Точечно: в «Мои репо» удержание репозитория → «🧹 Очистить артефакты этого репозитория»,
на экране артефактов — «🗑 Удалить все артефакты (N)».

Что ещё занимает квоту: старые артефакты в **других** репозиториях аккаунта
(экран как раз проходит по всем), а также артефакты удалённых ветвей и давних запусков —
их и снимают фильтры «старше 7/30 дней».

## 💾 Сколько места занято на GitHub

Экран **«Хранилище GitHub»** (⋮ на главном, ⋮ на экране артефактов) считает по данным API:

| Что показывает | Источник |
|---|---|
| Занято аккаунтом и лимит плана, «осталось» + полоса заполнения | `GET /user` → `disk_usage`, `plan.space` |
| Репозиториев доступно, суммарный размер, топ-10 самых больших | `GET /user/repos` → `size` (КБ) |
| Размер открытого репозитория | `GET /repos/{owner}/{repo}` → `size` |
| Артефакты Actions (живые и истёкшие) и кэш Actions | `/actions/artifacts`, `/actions/cache/usage` |
| Платное хранилище за месяц и дни до конца периода | `/users/{login}/settings/billing/shared-storage` |

Оговорки выведены на самом экране: `size` — это git-история без релизов/Packages/артефактов;
артефакты и кэш входят в квоту Actions (бесплатный план — 500 МБ для приватных репозиториев,
для публичных бесплатно); биллинг-эндпоинт требует classic-токен со scope `user`
(fine-grained — `Plan: Read`), при отказе экран показывает причину.

## 🩺 Если установщик пишет «пакет недействителен»

Это `INSTALL_FAILED_INVALID_APK`: APK отклонён на проверке, а не «сломался».

| Причина | Как проверить | Что делать |
|---|---|---|
| На телефоне сборка с **большим versionCode** | ⋮ → «О приложении»: там версия и versionCode | поставить сборку с большим versionCode (в 3.1 это **30**) |
| Старая копия подписана **другим ключом** | в диалоге после скачивания показан SHA-256; сертификат — `CN=ZI Git, O=ZI, C=BY` | удалить старое приложение и установить заново (токен ввести снова) |
| Файл скачался не полностью | размер в «Файлах» должен совпадать с артефактом | скачать заново — приложение теперь само проверяет APK |
| Установленная версия портит APK при распаковке | «пакет недействителен» сразу после скачивания из старой версии | ставить APK из **Releases** (без zip и распаковки) |

Самый надёжный путь — **APK из релиза**: вкладка «Релизы» в приложении или
github.com/…/releases.

## ⚙️ Сборка в GitHub Actions

`.github/workflows/build-apk.yml` собирает APK тем же `build.sh` (без Gradle):
JDK 21 + Android SDK → сборка → проверка подписи.

Для тегов `v*` в релиз прикладываются **чистые .apk**, без zip-архивов, под теми же именами,
что и раньше: **`ZI-Git.apk`** (его ищет автообновление) и **`ZI-Git-v<версия>.apk`**.

В Actions APK дополнительно лежит артефактом `ZI-Git-APK-<версия>` — GitHub всегда упаковывает
артефакты в zip, это ограничение самого GitHub, а не сборки. Приложение распаковывает архив само
и сохраняет готовый `.apk` в «Загрузки», так что ставить можно сразу.

Если сборка падает, лог выкладывается в ветку `ci-log`.
